1. Resumo Executivo

O Navalha é um sistema completo de gestão para barbearias, desenvolvido em fases incrementais. Esta entrega corresponde à Fase 1, que estabelece toda a fundação técnica e os cadastros mestres necessários para o funcionamento do negócio.

✅ O que está pronto

  • Login por papel (Cliente, Barbeiro, Administrador)
  • Cadastro e gestão de Serviços
  • Cadastro e gestão de Barbeiros (comissão, serviços)
  • Jornada de trabalho semanal (múltiplos turnos/dia)
  • Interface web responsiva (4 telas dedicadas)
  • Testes automatizados (9 testes passando)
  • Segurança nível produção

🎯 Princípios de Design

  • Zero dependências externas
  • Deploy trivial (copia pasta, roda)
  • Banco SQLite — backup = copiar arquivo
  • Preços em centavos (inteiros)
  • Soft delete (desativa, não apaga)
  • Permissão checada no servidor

2. Funcionalidades por Papel

👤 Cliente

  • Criar conta (nome, e-mail, telefone, senha)
  • Entrar / Sair com bloqueio após 5 tentativas
  • Ver serviços ativos (duração, preço)
  • Ver barbeiros ativos + serviços + horários

✂️ Barbeiro

  • Credenciais criadas pelo admin
  • Ver própria jornada (dias, turnos, serviços)
  • Ver comissão percentual configurada
  • Não acessa painel admin, outros barbeiros

🛠️ Administrador

  • Serviços: CRUD + ativar/desativar
  • Barbeiros: Cadastrar (login, comissão %, serviços), editar, desativar
  • Jornada: Definir horários semanais, múltiplos turnos, sem sobreposição
  • Visão total: Vê todos serviços/barbeiros (incl. inativos)

Regra de negócio: Serviços e barbeiros nunca são apagados, apenas desativados (ativo: false). Isso garante integridade dos agendamentos futuros (Fase 2).

3. Tecnologia e Arquitetura

CamadaTecnologiaJustificativa
RuntimeNode.js 22.13+ (LTS)Suporte nativo a SQLite, fetch, test runner
Servidor HTTPnode:http nativoZero dependências, controle total, performance
Banco de DadosSQLite (node:sqlite)Arquivo único, WAL mode, backup trivial, ideal p/ barbearia única
Criptografianode:crypto — scryptPadrão moderno, resistente a GPU/ASIC, salt único por usuário
FrontendHTML5, CSS3, JS ES ModulesSem build step, cacheável, leve, funciona offline
Testesnode:test nativoZero config, roda em CI sem dependências

Por que Zero Dependências?

  • Segurança: Zero vulnerabilidades de supply chain (npm audit = clean)
  • Confiabilidade: Zero npm install quebrado, zero breaking changes de libs
  • Deploy: Copia a pasta → node server.js → funciona
  • Longevidade: APIs nativas do Node são estáveis por décadas

5. API REST — Resumo

MétodoRotaPapelDescrição
POST/api/auth/cadastroPúblicoCria cliente + login automático
POST/api/auth/loginPúblicoLogin (bloqueio 5 tentativas)
POST/api/auth/logoutLogadoEncerra sessão
GET/api/auth/meLogadoDados do usuário atual
GET/api/servicosPúblicoServiços ativos (admin vê todos)
POST/PUT/api/servicosAdminCriar/editar serviço
GET/api/barbeirosPúblicoBarbeiros ativos + serviços + horários (sem dados sensíveis)
POST/PUT/api/barbeirosAdminCriar/editar barbeiro

GET/api/meu-barbeiroBarbeiroPróprio cadastro e jornada

Nota: Preços armazenados em centavos (inteiro) — evita erros de ponto flutuante. Jornada: dia_semana 0 (dom) a 6 (sáb), horários HH:MM, múltiplos turnos/dia sem sobreposição.

6. Como Rodar em Produção

Pré-requisitos

# Node 22.13+ (LTS)
node -v

Variáveis de Ambiente (Recomendadas)

export ADMIN_EMAIL="admin@suabarbearia.com"
export ADMIN_SENHA="SenhaForte123!"
export PORT=3000
export DB_FILE="./data/barbearia.db"
export COOKIE_SECURE=1    # obrigatório se usar HTTPS

Iniciar

node server.js

Primeira execução sem ADMIN_SENHA: o sistema gera uma senha aleatória segura e mostra uma única vez no console. Anote-a.

Deploy com HTTPS (Recomendado)

# Exemplo com Caddy (automático Let's Encrypt)
suabarbearia.com {
  reverse_proxy localhost:3000
}

Com HTTPS ativo, defina COOKIE_SECURE=1 para cookies seguros.

8. Testes Automatizados

npm test

✅ Cobertura (9 testes)

  • Cadastro cliente (e-mail normalizado, validações)
  • Login/logout, bloqueio força bruta (429 após 5 tentativas)
  • Exigência Content-Type: application/json em escritas
  • Serviços: permissões, validações, ativo/inativo
  • Barbeiros: cadastro, jornada, visão pública sem vazamento, desativação derruba sessão
  • Rotas inexistentes e métodos errados (404/405)
  • Arquivos estáticos + proteção path traversal

🔧 Como rodar

# Roda todos
npm test

# Ou direto com Node
node --test test/api.test.js

Testes usam banco em memória (:memory:) — isolados, rápidos, determinísticos.
